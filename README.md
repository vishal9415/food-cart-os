# Food Cart OS

Self-serve ordering and operations platform for independent food carts.

## Product model

- **Owner app:** Owners create an account, create one cart, manage menu and availability, receive orders, review sales and share a unique QR code.
- **Customer ordering:** Customers scan the cart QR code and open a mobile web menu in their browser. No customer app or account is required.
- **Payments:** Cash at pickup only. The checkout does not collect online payments.
- **Mobile distribution:** The owner experience is being packaged for Android and iOS using Capacitor. The QR customer experience remains web-based.

## Local setup

1. Install Node.js 22 or newer.
2. Run `npm install`.
3. Copy `.env.example` to `.env.local`.
4. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`.
5. Run `npm run dev`.

Never place a Supabase secret/service-role key or payment credentials in a `VITE_*` variable.

## Routes

- `/owner` — owner sign-in, self-registration and cart setup.
- `/c/:slug` — public QR ordering page for an individual cart.
- `/` — legacy demo cart route, currently mapped to `the-food-cart`.

## Native app setup

The native owner app uses Capacitor and opens directly into the owner workspace. Native email confirmation and password recovery use the `foodcartos://auth/callback` URL scheme; add that exact URI to Supabase Auth allowed redirect URLs before testing these flows:

```bash
npm install
npm run build
npx cap add android
npx cap add ios
npx cap sync
npx cap open android
npx cap open ios
```

Android builds require Android Studio and an Android SDK. iOS builds require macOS and Xcode. Native platform folders are generated by Capacitor and should be committed after their first successful setup. Store listing assets, privacy policy, signing certificates, developer accounts and final release review are still required before Play Store / App Store submission.

## Multi-cart data model

- `carts` is the tenant record and owns the public slug.
- `cart_members` assigns owner/manager/operator access per cart. The owner-scoped `manage-cart-members` Edge Function handles invitations and membership changes.
- `menu_categories`, `menu_items`, `store_settings` and `orders` carry `cart_id`.
- Guest order sessions and saved receipts are scoped to a cart so one cart cannot read another cart's order history.
- Cart membership checks use a private-schema security-definer helper; guest session/idempotency tables remain inaccessible to anon/authenticated API roles.
- Menu pricing and order totals are calculated server-side.
- Cart creation is handled by the `create-cart` Edge Function and a privileged database RPC.
- Guest checkout is handled by `create-guest-order`; customer order recovery is handled by `get-customer-orders`.
